# GPU backends of the generic-parallel interface in mfem-mgis (11/10/2026)

Script: `cases/measure-backends-gpu.sh`. Beam r4 (111,843 unknowns, 10
steps) on one process and the GPU, everything by kernels, assembled
tangent, Newton and PCG + BoomerAMG; behaviour
IsotropicLinearHardeningPlasticity generated by the generic-parallel
interface with each configuration of TFEL for the GPU. mfem-mgis
517e33cde4 (`build/cases-others`; the "mfem-mgis" line of `summary.txt`
gives the version of the sources, not the one of the linked library).
Libraries of the measurement generated by hand with the same
configurations (variable `libs` of the script), then built by CMake in
`build/cases-others/beam/generic-parallel-*`. Quiet machine, two passes.

## Which backends work in mfem-mgis

| Configuration | Result |
|---|---|
| cuda-nvcc | works |
| cuda-clang | works |
| hip-clang-nvidia-platform | works |
| hip-hipcc | works |
| kokkos | works if the program initialises Kokkos (option `--kokkos` of the beam, `cases/common/KokkosRuntime`); otherwise "Kokkos is not initialized" |
| sycl-default-acpp | refused: "no SYCL queue given", the program must provide a SYCL queue in the execution options |
| stlpar-parunseq-nvhpc-gpu | fails ("libgomp: TODO"): the OpenMP runtime of nvhpc conflicts with libgomp, loaded by MFEM and mfem-mgis compiled by GCC |
| openmp-offload-nvhpc-gpu | same |

The five backends that work give the expected norm on the short test (r1,
3.264041277, the one of the behaviour generated by the `generic`
interface) and, in r4, 48.83704586, like the previous measurements of the
beam with Newton and PCG + BoomerAMG (48.83704551 to 48.83704606 depending
on the number of processes and the settings, tolerance of the iterative
solver). Same Newton iterations (32; a permutation of two steps for kokkos
in the first pass, same total).

## Times (seconds)

| Configuration | Loop over the steps (two passes) | Integration (42 calls) |
|---|---|---|
| cuda-nvcc | 3.04 and 3.28 | 0.05 |
| cuda-clang | 3.15 and 3.08 | 0.05 |
| hip-clang-nvidia-platform | 3.10 and 3.42 | 0.05 to 0.06 |
| hip-hipcc | 3.10 and 3.12 | 0.05 |
| kokkos | 3.17 and 3.09 | 0.04 |

- On this case, the behaviour costs about 1 ms per integration (a bit less
  with kokkos: 0.039 and 0.041 s for the 42 integrations, against 0.050 to
  0.055 s, in both passes): the differences of the loop over the steps (up
  to 13 %, from 3.04 to 3.42 s) are noise, the linear solve dominating (2.2
  to 2.5 s).
- To separate the backends on the integration, an expensive behaviour is
  needed (polycrystal, ex8).
