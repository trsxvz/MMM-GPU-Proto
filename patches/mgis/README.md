# Patches

Series of patches giving the MGIS of the prototype from MGIS master, commit
`a30dbf5` (20/10/2026):

```bash
git clone <official MGIS repository> mgis && cd mgis
git checkout a30dbf5
git am /path/to/patches/*.patch
```

Patches, by subject (independently of their numbers; the details are in
`docs/mgis.md` of the prototype):

- batches of behaviours and models generated by the `generic-parallel`
  interface of MFront: loading and checks, copies of the data structures
  of TFEL, integration without copy, automatic switch of the existing
  functions, initialize functions, post-processings, rotations (finite
  strain behaviours included), refusal of the functions of a point for a
  library which does not provide them;
- execution policies, memory spaces and memory resources, location of the
  arrays of a material data manager checked against the backend,
  asynchronous computations;
- material properties of the `generic-parallel` interface: loading,
  `evaluate`, execution policies, asynchronous evaluations, statistics and
  statuses. Patch 0079 follows version 3 of the functions of TFEL: copies
  `mgis_mp_Batch<X>` of the data structures, checked member by member,
  loading by two independent tests (functions of batches if their version
  is exported, function of one point for the `generic` interface);
- views and layouts: `FieldView` and `MaterialDataView`, layout of the
  arrays of the material data managers (point by point or component by
  component), views on the variables of a state, rotations and
  evaluations on views, HDF5 files and C, Fortran and Python bindings
  following the layout;
- end of time step on the arrays of the calling code (`FieldOperations`,
  headers for CUDA, HIP, SYCL, Kokkos, RAJA, OpenMP, OpenACC and the
  parallel algorithms of C++, with tests compiled by `nvc++ -stdpar=gpu`),
  view without the check of the values held on the host
  (`make_unchecked_view`), update of the inputs of a state only
  (`updateInputValues`);
- profiling: synchronization function called around the timed sections
  (`setProfilingSynchronization`);
- fixes: material axes of the rotation matrices, uniform material
  properties given by a span, statuses of the failures of the initialize
  functions and post-processings, memory resources with stricter
  alignments, thread pools, copies of the rotation matrices, outputs of
  the failing points;
- no allocation on the heap in the usual calls, tests (CPU and CUDA) and
  documentation (headers and web pages);
- single precision (patches 0062 to 0068): option `MGIS_REAL_TYPE`,
  numerical type checked at the loading of each entry point, tests in
  float on the CPU and with CUDA, documentation;
- displacement gradient (patches 0069 to 0075): initialize functions and
  post-processings given the options of the behaviour, option to give the
  displacement gradient to the finite strain behaviours, bindings, axial
  deformation gradient of plane stress initialized to one, tests against
  analytical solutions;
- version 3 of the functions of batches (patches 0079 to 0086): material
  properties and behaviours, copies of the structures of TFEL checked
  member by member, report functions of the libraries, functions of
  batches and of a point detected independently, libraries also
  containing the functions of the `generic` interface, documentation;
- execution policies of the backends (patches 0087 and 0088): the
  execution policies of MGIS hold a pointer to the policy of the backend
  defined by TFEL (declared only, MGIS still builds without TFEL), copies
  of the version 4 of the data structures, identifier of the expected
  policy in the descriptions, tests of the rules.
- Arcane (patch 0089): field operations launched on a queue of Arccore,
  the core component of the Arcane framework, and memory resource of the
  unified memory of Arccore, counterparts of the `arcane` backend of
  MFront;
- name of the execution policy whose report is deferred (patch 0090):
  `DeferredReportBatchExecutionPolicy`, formerly
  `AsynchronousBatchExecutionPolicy` (the computations are asynchronous if
  the policy of the backend requests it).
